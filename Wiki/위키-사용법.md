> 현금 보유 수준과 향후 1년 주가 수익률에 관련된 자료를 Raw에 넣으면 변수 정의·근거·노하우를 Wiki에 연결해 축적할 수 있습니다. 연구 주제는 기록했고, 세부 설계와 자료 내용은 학생 확인을 거쳐 정리합니다.

## 처음 시작할 때

[연구계획 초안](../research_plan.md)에 학생이 제시한 「기업의 현금 보유 수준과 향후 1년 주가 수익률의 관계」를 기록했습니다. 세부 내용을 정하면 대화로 알려주거나 계획 파일에 반영할 수 있습니다. [[연구-개요]]에도 함께 반영하며 정하지 않은 항목은 확인 필요로 남깁니다.

자료는 `Raw/`에 하위 폴더 없이 넣습니다. 구별하기 쉬운 파일명을 사용하면 출처 추적에 도움이 됩니다. 원본은 에이전트가 수정하지 않습니다.

대화로 원본을 업로드하고 Raw 보관·정리를 요청해도 됩니다. 요청 범위에서 첨부 바이트 그대로 최초 등록하고 파일 지문을 대조합니다. 기존 원본은 덮어쓰지 않습니다. 현재 논문 세 편은 이 방식으로 Raw에 등록했습니다.

각 작업에서 먼저 [[index]]와 관련 페이지를 읽습니다. 원문을 읽은 것과 학생이 내용을 확인한 것은 구분하며, 학생 확인 전의 내용은 검증 완료로 표시하지 않습니다.

## 1. 자료 넣기

> “Raw에 넣은 선행연구 PDF를 읽고 내 연구계획에 맞춰 위키에 반영해줘.”

관련 개념·방법·근거는 기존 페이지에 통합하고 필요하면 새 페이지를 만듭니다. 새 페이지는 연구 관점의 takeaway로 시작하며 관련 페이지와 연결합니다. [[index]]와 [[log]]도 함께 갱신합니다. 읽지 못한 표·수식·페이지나 근거가 부족한 판단은 확인 필요 상태로 남깁니다.

자료별 출처 요약과 여러 자료를 연결하는 개념·방법론·비교·종합 페이지를 함께 관리합니다. 새로운 근거가 기존 설명과 다르면 조건·출처를 비교하고 영향을 받는 페이지까지 갱신합니다. 자세한 원리는 [[LLM-Wiki-운영-원리]]에서 확인할 수 있습니다.

원문 사실·저자 해석·AI의 종합·학생의 판단을 구분하고 계수·표본·단위·가정에는 근거 위치를 붙입니다. 없는 정보는 `확인 필요`로 남깁니다. 반대 증거도 보존해 표본·기간·방법·가정 등 비교 가능한 차이를 설명합니다. 페이지 삭제·병합이 필요하면 먼저 제안하고 학생이 결정합니다.

여러 파일 중 일부만 처리하려면 파일명이나 범위를 지정할 수 있습니다. 기존에 처리한 원본은 파일 지문을 대조해 중복 정리를 피합니다.

## 2. 질문하기

> “선행연구에서 사용한 방법은 내 연구에 어떤 조건에서 적용할 수 있어?”
>
> “이 오류를 전에 해결한 기록이 있는지 찾아서 절차를 알려줘.”

위키를 검색하고 관련 페이지의 교차참조와 원본을 따라 답합니다. 근거·해석·미확인 사항을 구분하며 필요한 경우 어떤 추가 자료가 있어야 판단할 수 있는지 알려줍니다. 재사용할 가치가 있는 답변은 근거와 함께 Wiki에 누적할 수 있습니다.

여러 논문의 비교나 재현 가능한 해결책처럼 가치 있는 답변은 기존 페이지에 통합하거나 종합 페이지로 저장합니다. 이후 질문은 이렇게 축적된 연결과 근거를 먼저 활용합니다.

현재 자료로 해볼 질문 예시: “세 논문의 현금 측정과 결과가 어떻게 다르고, 내 향후 1년 주가 수익률 연구에 각각 어디까지 적용할 수 있어?” [[선행연구-현금보유논문비교]]와 연결된 정의·결과 페이지를 함께 활용할 수 있습니다. 학생이 2026-10-07 실제로 같은 취지의 질문을 요청했고 [[선행연구-현금보유논문비교]]의 Query 절에 답을 저장했습니다.

## 3. 건강검진

> “위키 건강검진 해줘. 깨진 링크와 출처 누락, 연구계획과 맞지 않는 내용을 찾아줘.”

플랫 구조, 첫 callout, 목차·링크, 중복·고립 페이지, 출처, 상충 주장, 원본 변경, 연구계획과의 정합성을 점검합니다. 점검 결과와 수정 제안을 먼저 보고하고 형식·연결 오류를 보완합니다. 삭제·병합은 학생이 결정한 뒤에만 수행하고 [[log]]에 기록합니다. 내용 판단에 자료가 더 필요하면 `확인 필요`로 남깁니다.

반복해서 등장하지만 정리되지 않은 개념, 새 출처로 대체된 오래된 설명, 데이터 공백과 추가 조사 질문도 찾습니다. 근거 없는 빈 페이지는 만들지 않습니다.

## 출처와 현재 한계

- 이 사용법은 사용자의 위키 생성 요청과 [관리 규칙](../AGENTS.md)에 기반합니다.
- 제공된 LLM Wiki 전문을 읽고 누적 운영 방식을 반영했습니다. 참고 요약과 적용 판단은 [[LLM-Wiki-운영-원리]]에 기록했습니다.
- 초기 논문 두 편의 읽기·위키 반영과 학생의 부분 확인·사용 허가를 기록했고, 신규 초과현금 논문 S3도 반영했습니다. S3의 대표 확인 필요 5개 묶음은 학생 확인 대기입니다. 관리 항목 11개 중 7개 확인 완료·3개 추가 사용 허가·1개 재현성 한계이며, 상세 판단과 읽기 범위는 [[선행연구-현금보유논문비교]] 및 각 출처 요약에 있습니다. 세부 설계는 미정이며 원자료 실증 분석은 수행하지 않았습니다.
- 마크다운 파일을 기반으로 에이전트와 대화하며 사용하는 위키입니다. 위키링크의 클릭 이동은 해당 문법을 지원하는 편집기에서 사용할 수 있습니다.

## 과제 진행 상태

- **2-3 Wiki 만들기 — 수행:** 현재 논문별 요약 3개와 공통 개념·비교 페이지 5개를 플랫 Wiki에 작성하고, [[현금보유-측정과변수정의]] 등의 실제 페이지로 교차참조했습니다. 논문별 관리 항목의 확인·추가 사용 허가·한계를 기록했으며 나머지 지식은 학생 확인 대기입니다.
- **Obsidian Graph View:** `Raw/`·`Wiki/`가 포함된 저장소 사본을 로컬에서 vault로 열면 교차참조를 볼 수 있습니다. 이 작업에서 Obsidian 실행이나 그래프 화면 확인은 하지 않았습니다.
- **2-5 추가 Ingest — 수행:** 초기 두 자료 이후의 신규 S3를 Raw에 등록하고 기존 Wiki와 비교·통합했습니다. [[논문-초과현금과주주가치-신민식-2012]]·[[초과현금-측정과보유기간초과수익률]] 및 [[선행연구-현금보유논문비교]]에서 결과를 확인합니다.
- **2-5 Query — 수행:** 학생이 세 논문의 현금 측정·결과·내 1년 수익률 연구의 활용 범위를 질문했습니다. 기존 비교·변수·결과·출처 요약을 함께 읽고 핵심 원문을 재확인해 [[선행연구-현금보유논문비교]]의 Query 절에 저장했습니다. 답변 내용과 설계 제안은 학생 확인 대기입니다.
- **2-5 Lint — 다음 단계:** “현재 위키 전체에서 출처 없는 주장, 모순, 고립 페이지, 오래되었거나 확인 필요한 내용을 찾아줘”라고 요청합니다. 이번 Ingest의 원본·형식·링크 검사는 전체 Lint 실습과 구분합니다.

## 로컬 사용 — GitHub 복제와 Obsidian Graph View

학생은 2-5로 진행하겠다고 요청했고 이번 추가 Ingest를 수행했습니다. 세 논문 비교 Query도 수행했으며 다음 실습은 전체 Lint입니다. 아래는 로컬 복제·그래프 확인 절차를 계속 참고할 수 있게 유지합니다. 실제 Graph View 실행과 화면 확인은 학생의 컴퓨터에서 진행합니다. 저장·업로드 결과는 [[log]]에서 확인하며, GitHub API의 403 응답과 실제 Git 저장소 연결의 성공 여부를 구분합니다.

1. GitHub Desktop에 로그인하고 **File → Clone repository → URL**에서 `https://github.com/ViceversaOO/AI.git`를 복제합니다. 브랜치는 `main`을 사용합니다.
2. Obsidian에서 **폴더를 보관함으로 열기(Open folder as vault)**를 선택하고 복제한 `AI` 폴더를 엽니다.
3. `Wiki/index.md`를 열어 논문 요약과 공통 개념·비교 페이지를 확인합니다.
4. 명령 팔레트에서 **그래프 보기 열기(Open graph view)**를 실행합니다. 단축키는 Windows/Linux `Ctrl+P`, macOS `Cmd+P`입니다.
5. 그래프 검색에 `path:Wiki`를 넣고 논문 3개가 현금 측정·동기·결과변수 구분·비교 페이지와 선으로 연결되는지 확인합니다. 목차·로그가 화면을 가리면 `path:Wiki -file:index -file:log`로 좁힐 수 있습니다.
6. 과제 기록용 화면을 캡처합니다. 새 자료 추가 후에도 같은 그래프를 다시 확인할 수 있습니다. 현재 신규 Ingest와 Query는 수행했고 전체 Lint가 남아 있습니다.

GitHub의 **Code → Download ZIP**으로 파일을 한 번 내려받아 Obsidian에서 열 수도 있습니다. 지속적인 수정·동기화에는 GitHub Desktop 복제를 사용합니다. 클라우드 내부 `/workspace/...` 경로 링크는 실제 다운로드 게시 기능과 구분합니다.

## 직접 수정하고 동기화하기

- 수정 전 GitHub Desktop에서 **Fetch origin**, 필요한 경우 **Pull origin**으로 최신 내용을 받습니다.
- Obsidian에서 `.md`를 직접 수정하고 저장합니다. `Raw/` 원본은 수정·삭제·이동하지 않습니다.
- GitHub Desktop에서 변경 내용을 확인하고 **Commit to main → Push origin**으로 GitHub에 저장합니다.
- 다음 Codex 작업은 이 저장소의 `main`을 기준으로 시작합니다. 진행 중인 작업에도 반영하려면 ‘GitHub의 최신 변경을 읽고 이어서 작업해줘’라고 알려주세요.

로컬·GitHub·클라우드는 자동 동기화되지 않습니다. 동시에 같은 파일을 수정했다면 양쪽 내용을 비교해 충돌을 해결합니다. 상세 복제·명령 안내는 [README](../README.md)에 있습니다.

현재 참고문서는 루트의 [LLM Wiki 원문 보존 사본](../LLM-Wiki-참고원문.txt)으로 함께 보관합니다. 과거 로그의 저장소 밖 첨부 링크는 당시 경로이며 현재 탐색에는 이 사본을 사용합니다. 생성 ZIP과 기기별 Obsidian 창 배치는 버전 관리에서 제외합니다.
